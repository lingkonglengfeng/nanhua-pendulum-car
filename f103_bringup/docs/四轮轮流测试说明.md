# 四轮轮流测试（临时固件 0x103C8006）

这是用于确认新板实际轮位的测试版本。通道编号暂不等于源码旧注释中的轮位，不据图纸提前重排。

已用本机 ARMCC 5.06 update 5 完整重编译35个源文件，并将警告视为错误，编译与链接通过。ROM占用约17.30KiB，RW/ZI约11.46KiB；尚未进行实车验证。

可烧录文件：`MDK-ARM/sequence_test_build/f103_wheel_sequence.hex`。对应带调试符号的文件为同目录 `f103_wheel_sequence.axf`。Keil原输出位置 `MDK-ARM/f103_bringup/f103_bringup.axf` 和 `.hex` 也已同步为本次固件，原产物备份在 `sequence_test_build/before_sequence_f103_bringup.*`。

本机构建脚本位于 `MDK-ARM/sequence_test_build/build_sequence.ps1`，读取原Keil工程的源文件清单和包含目录进行编译，不修改工程中的工具链及软件包选择。

## 运行方式

编译下载并复位后，测试会自动运行一轮。先将四轮架空、看清车头方向，再运行固件。

| 复位后相对时间（从控制任务开始计时，约值） | 动作 |
|---|---|
| 0–3秒 | 全部停止，等待观察 |
| 3–5秒 | 通道0转动 |
| 5–6秒 | 全部停止 |
| 6–8秒 | 通道1转动 |
| 8–9秒 | 全部停止 |
| 9–11秒 | 通道2转动 |
| 11–12秒 | 全部停止 |
| 12–14秒 | 通道3转动 |
| 14秒以后 | 全部停止，本轮完成 |

默认输出为25%，每次只有一路有驱动命令。正命令的实物转向待观察，不预先称为“前进”。四轮会有短暂惯性滑行，以上时间是驱动命令时序。

测试与 AS5600 读角、编码器采集一起由原200Hz任务执行；传感器无效不会阻止本次电机识别测试。测试期间会清零 g_bal_enable 和 g_motor_test_enable，结束后不会自动进入直立或旧台架模式。

## Keil Watch

| 变量 | 用途 |
|---|---|
| g_fw_build | F103应为0x103C8006，确认烧录版本 |
| g_motor_seq_enable | 0停止；完成后写1再运行一轮（重新等待3秒） |
| g_motor_seq_pwm_pct | 0–100，默认25；若轮子不动，可先停止，改成30再运行 |
| g_motor_seq_wheel | 当前选中通道0–3；255表示未选中；间隔时保留刚运行的通道号 |
| g_motor_seq_state | 0空闲、1等待、2转动、3间隔、4完成 |
| g_motor_seq_completed | 已完整完成的轮次，停止中断的一轮不计入 |
| g_motor_seq_enc_delta | 4×4矩阵：第i行记录驱动通道i运行期间，各编码器通道的计数变化 |

观察编码器时将矩阵展开，保留一轮结束后的数据即可。正负号仍应用旧 g_enc_sign，尚不作为新板前进方向的最终标定；本阶段先判断哪一路在变化。重新启动一轮会清除上一轮矩阵。

旧的 g_motor_test_* 仍保留原始引脚测试含义；本次不使用它们。不要把原始PWM占空比当作反向速度百分比。
