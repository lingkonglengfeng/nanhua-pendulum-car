# 退出诊断与200RPM阈值

2026-10-18，固件 `0x103C8035`。用户要求不再依赖Watch确认退出原因，改为退出时直接串口打印；并明确把任一轮绝对速度60RPM连续50ms退出改为200RPM连续200ms。已实现、编译和回归通过，未自动烧录或驾驶实车。

## 默认退出设置

源码 `g_bal_max_rpm=200.0f`，`BAL_OVERSPEED_DWELL_MS=200U`。任一轮原计数测速的绝对值严格大于200RPM，整车最大单轮值连续超限达到200ms才退出。所有轮都降回不超过阈值时，连续计时清零；195ms不足，200ms触发。按现有“整车任一轮峰值”规则计时，不要求始终是同一轮超限。

速度保护仍使用旧计数加20ms低通的g_speed_fast，不受混合测速变平滑影响。角度退出180°±30°、±1.4°连续400ms捕捉、80%共同输出、12%差动、位置/速度/转向PID及不限时保留。位置保持回正速度上限仍6RPM；提高超速退出阈值不会把位置环目标改成200RPM，也不代表位置/速度跟踪已经稳定。

BALSAFE第一项仍可改速度阈值，第二项仍是总运行时限，**不是200ms超速持续时间**：

```text
BALSAFE 200 0
```

表示200RPM、关闭总运行时限，超速持续时间由本版固定200ms。BALSAFE是停止类配置命令，配置后再ZERO或ARM。旧脚本若继续发BALSAFE60/0，就会将阈值改回60RPM；X/V会显示实际阈值，不能只看固件默认。

## 退出诊断

在BAL_ACTIVE离开时，控制模块先冻结原因和观测值，再执行原控制清零/撤驱动逻辑。串口任务等待当前DMA包结束，优先于参数包发送一个带表头的退出事件：

```text
#X,ms,reason,code,peak_rpm,max_rpm,overspeed_ms,dwell_ms,raw_angle_deg,run_ms,coalesced
X,12345,SPEED,8,215.25,200.00,200,200,2.100,32000,0
```

上例是格式示例，**不是新一轮实车测量**：峰值轮速215.25RPM超过实际阈值200RPM，连续200ms，原始直立偏角2.1°，原因为SPEED。

| reason / code | 含义 |
| --- | --- |
| STOP / 1 | 人工STOP或停止类模式切换 |
| ANGLE / 2 | 原始摆角偏差超出退出角度 |
| SENSOR / 3 | 角度或速度反馈无效 |
| TIMING / 4 | 控制间隔异常 |
| ZERO / 5 | 标定状态无效 |
| CONFLICT / 6 | 控制模式冲突 |
| CONFIG / 7 | 控制参数越界或NaN |
| SPEED / 8 | 持续超速 |
| RUN_TIME / 9 | 配置的总运行时限到达 |

raw_angle_deg是相对直立点0°的原始偏差，不是最低点为0°时的绝对角；角度200°对应直立偏角+20°。peak_rpm为退出检查时最近可用的最大单轮绝对速度，不是整段试验历史最大值。ms/run_ms取退出时的控制采样时刻；人工停止可能对应上一控制采样。角度和早期有效性退出在当轮测速提交之前发生，其峰值测速可比角度早一个控制周期。

普通参数流依然仅ACTIVE，新增一次性X是用户明确要求的例外。LOG0也保留X；上电OFF、等待捕捉、非ACTIVE标定失败不会循环打印退出信息。人工STOP会打印STOP，避免将人为停止误认作保护。未配置打印代码的旧v34本次退出不会因后续烧录自动补出诊断，必须用v35重新测试。

控制任务不等待串口、不作字符/浮点格式化。仅增加一个28字节固定槽，模块和日志任务用现有临界区同步Peek/Ack；事件在DMA忙时保留，重新ARM/ZERO不会覆盖已冻结记录。DMA包正常发布后确认并清槽，不反复打印。若串口长时间无法发送而连续产生多个退出，保留最早待发事件，coalesced表示合并的后续退出次数，不能将其当成无限事件队列。底层UART/DMA物理发送失败时仍可能丢包，原DMA错误与超时计数保留，X不提供额外重发协议。

## 操作

烧录正常Keil HEX/AXF，摆杆自然下垂且静止发送：

```text
STOP
BALSAFE 200 0
ZERO
```

进入直立、开始打印后按需BALPZERO启用当前位置0保持。下次发生退出，直接将包含末段T/P/Y/H/O和X的整段日志发回，不需查看Watch。若是手推、碰轮、提车、过坎或碰撞，请同时注明。
