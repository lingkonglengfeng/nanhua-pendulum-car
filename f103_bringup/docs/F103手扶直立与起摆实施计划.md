# F103 小车倒立摆审阅与分阶段实施计划

日期：2026-10-16。

本轮范围：审阅现有代码和机械资料、制定计划；不修改固件、不烧录。用户已确认上电自转问题解决，不再作为未完成故障。

## 1. 目标与当前依据

先实现：手扶摆杆到直立附近，释放后小车主动维持摆杆直立；再实现：减少车体漂移、提高重复性；最后考虑从自然下垂自动起摆并切入直立。

当前平台为 STM32F103C8T6 + 两块 AT8236 双路模块 + 四路带编码器减速电机 + AS5600。机械结构沿用 D:\blance_car 内的单轴倒立摆。根据最新 HARDWARE_SELECTION.md 和底板 V3 资料：

- 底板为 300×200×4 mm；四轮为普通轮，当前记录是 12V 370、减速比 21.3、空载 280rpm。
- 摆轴距底板名义高度 320mm，轴心到杆端 280mm，Ø8 铝管、608 轴承、AS5600 和可调配重。
- 轮径资料存在 65/66mm 两种标注，最终用实测滚动周长换算速度和位移。
- 整车装配 V1 中 520 电机、320×220 底板和旧驱动外形是历史占位，不作为当前硬件参数。
- 280mm 是杆端长度，不等于转动总成的重心距离或动力学等效摆长；配重位置也不能直接当作重心距离。
- 上述尺寸来自设计资料，实车质量、重心、摩擦、齿隙、轮胎滑移和运行时延尚未实测。

## 2. 工程审阅结论

可以沿用现有工程，无需从头重写。已有 TIM1 四路 PWM、A 相双边沿 EXTI 编码器、AS5600 软件 I2C、跨零角度解算、零点采样、角速度低通、200Hz 控制任务和 Watch 调参变量。

现有闭环实际只有 u = Kp*theta + Kd*omega，然后向四个轮子施加同一个有符号命令。Kp、Kd 初值均为 0，默认关闭。编码器只生成增量，尚未进入稳摆控制；当前没有位置反馈、速度反馈、起摆控制和捕捉状态机。G474 旧工程中可见的 Control_Task 主要是 AS5600 读数，也不能作为已有实车稳摆参数来源。

### 2.1 高优先级：轮序与新板不一致

依据用户本轮提供的原理图和当前 app_vehicle.c，当前数组索引的实际对应如下。物理轮位是按原理图网络标签推断，实施前需用单轮通电和手转编码器核实实物。

| 当前索引 | 源码注释轮位 | PWM / IN2 | 按新图对应电机 | 编码器 A/B | 按新图对应编码器 |
|---|---|---|---|---|---|
| 0 | 右前 | PA8 / PA2 | 左前 FL | PA0 / PA1 | 左前 FL |
| 1 | 左前 | PA9 / PA3 | 右前 FR | PA4 / PA5 | 左后 RL |
| 2 | 右后 | PA10 / PB14 | 左后 RL | PA6 / PA7 | 右前 FR |
| 3 | 左后 | PA11 / PB15 | 右后 RR | PB12 / PB13 | 右后 RR |

其中索引 1、2 的电机和编码器按新图并不配对。当前四轮共同输出时可能不明显，一旦加单轮速度反馈或左右分组会产生错误。

建议统一固定轮序为 FL=0、FR=1、RL=2、RR=3，沿用当前 PWM 通道顺序；调整编码器索引 1/2 的归属，同步头文件、Watch 表、接线表及正负号。若实物接线不同，以实测映射为最终依据。

原理图另有 H4 第3脚 PC8_RR_PWM 与 MCU 端 PA11_RR_PWM 不同名的问题。用户确认的自转故障已解决；这里仅保留一次 PA11 到驱动端的通断核对，不假设该网络问题仍存在。

源码位置：Core/Src/app_vehicle.c:287、308、489、497、505、513。

### 2.2 高优先级：标定有效标志与占位注释冲突

pendulum_angle_config.h 中 PENDULUM_ZERO_STORED=1，而 PENDULUM_UPRIGHT_RAW=3061 仍标注“占位值”。程序会把它当作已经完成的直立标定。

实施时先确认 3061 是否确为当前磁铁和摆轴安装下的实测值；若未确认，重新扶正标定。不要将任意上电姿态自动当零点。角度统一使用弧度，直立为 0，杆顶向车前为正；角速度使用 rad/s。

源码位置：Core/Inc/pendulum_angle_config.h:19；Core/Src/app_vehicle.c:530。

### 2.3 高优先级：台架测试与闭环使用不同的输出语义

闭环 s_motor_apply() 接收 [-1,1] 有符号命令，反向时会将占空比取补；台架测试直接写 CCR 与 IN2，且绕过 g_mot_sign。

结果：台架 dir=1、PWM=20% 对应约 80% 的反向驱动占比；PWM=0% 时是全反向。台架看到的方向也不一定等于闭环经过 g_mot_sign 后的方向。这会误导方向标定和低输出测试。

计划让台架测试和闭环共用同一个有符号电机接口；如保留原始引脚测试，明确区分“引脚占空比”和“电机驱动力命令”。正反转使用不同的续流/制动状态，不能假设同幅值命令在实车上响应完全对称，需测量。

源码位置：Core/Src/app_vehicle.c:320、658。

### 2.4 待测：角速度延迟与 5ms 实际周期

角速度滤波时间常数为 40ms，会在抑制噪声的同时引入延迟，是否合适要结合自由摆数据和闭环波形判断。AS5600 软件 I2C 的 F103 分支使用 100 次空循环延时和内部上拉模式，不能按文件开头旧注释推断实际总线频率。

当前周期统计记录任务执行用时，不能完整表示相邻两次采样间隔；毫秒分辨率也不足以分析细小抖动。计划同时记录采样间隔、传感读取耗时、控制耗时、漏周期和输出饱和，必要时用 DWT 或 GPIO 示波器测量。先保留 200Hz，测量结果证明有需要再提高频率。

源码位置：Core/Inc/pendulum_angle_config.h:27；Core/Src/pendulum_angle.c:149；Core/Src/as5600.c:38；Core/Src/app_vehicle.c:700。

### 2.5 文档与初始化需收敛

- 旧完整方案前半部分仍写裸机、旧引脚和定时器方案，当前实际为 FreeRTOS + TIM1 PWM + EXTI 编码器。
- TIM2 已用于 HAL 时基，不是空闲资源；SysTick 的实际归属以 FreeRTOSConfig.h 和编译符号为准。
- main.c 已先配置 HSE 72MHz，App_Init 又执行一次时钟重配；第一次 HSE 失败会先进入 Error_Handler，所以文档承诺的 HSI 回退路径并不完整。
- 这些应在基础整理阶段同步，避免调试时依照旧文档操作；本轮不执行重构。

## 3. 控制路线

这是一维小车倒立摆，主控对象是摆角 theta、摆角速度 omega，以及小车沿摆动方向的位移 x、速度 v。四轮底盘保持水平，不能直接照搬两轮自平衡车以车身倾角控制车速的模型。

第一步沿用角度 PD：u_theta = Ktheta*theta + Komega*omega。先用实车确定正负号、驱动响应和小范围稳定性，不从旧方案照搬数值。

第二步在角度内环稳定后，逐渐加入较慢、较弱的车速/位置反馈。可采用完整状态反馈形式 u = Ktheta*theta + Komega*omega + Kx*(x-x_ref) + Kv*v，各项符号由模型与实测统一。若采用串级形式，必须由小车倒立摆模型验证外环作用及带宽，避免位置环与直立环相互争抢。

初版不同时开启位置积分、四个高增益速度 PI 和航向闭环。先用统一前后命令实现直立，再按实测差异加入轮间补偿。若 PD 方案在测得延迟和执行能力下难以兼顾漂移与稳定，可基于实测模型设计 LQR；它不是首轮必须完成的前置工作。

## 4. 分阶段计划及验收

以下验收数字为拟定工程目标，不代表现有固件已经实现或实车能力承诺。保持相同配重、地面、电池条件并记录每次结果。

### 阶段 A：统一硬件与软件基线

1. 建立 FL/FR/RL/RR 的唯一配置表，核对 PWM、IN2、编码器 A/B 与实物。
2. 每次只测一个轮子，确认该轮对应的编码器变化；固化电机和编码器的独立方向符号。
3. 台架与闭环统一有符号输出接口。验证零、正、负命令及换向时实际引脚波形。
4. 同步接线文档、版本号、CubeMX 保留区；保留现有 RTOS 结构和 Watch 名称，减少无关改动。

验收：四轮都能正确点名、正反向可控；车辆前进时四路编码器统一为正；每轮电机和反馈一一配对。上电自转只作已解决问题的回归检查。

### 阶段 B：角度、速度和时序测量

1. 扶正采集零点，验证向前/向后倾斜角度符号及跨 4095/0 连续性；将实测标定与安装状态一起保存。
2. 固定配重质量与位置，记录静止噪声、手动摆动和自然下垂附近小幅自由摆的波形。
3. 实测轮胎滚动周长、每轮转一圈的计数；当前 A 相双边沿为 2 倍频，不能套用 4 倍频编码器的计数常数。
4. 将计数换算为米、米每秒，获得小车 x/v；比较滤波对噪声和时延的影响。
5. 增加轻量数据记录：时间戳、theta、omega、四轮增量/速度、x/v、u、实际限幅后输出、有效性和漏周期。优先低频导出，避免日志阻塞控制任务；是否使用 USART3/PB10/PB11 取决于当前转接板能否接出。

验收：静止与缓慢摆动读数稳定，方向和跨零正确；连续运行至少 60s 不新增通信错误/漏周期；正常任务最坏执行时间小于 5ms，目标留出至少约 40% 周期余量。高速编码器负载下也复核一次。

### 阶段 C：手扶释放后的直立

1. 保持车速/位置反馈为零，仅调整角度 PD。
2. 先确认杆向前倾时车轮命令使小车向前追杆。架空测试仅用于核对极性，稳定增益必须落地整定。
3. 从直立附近低角速度释放，逐步调整比例和阻尼；每次只改一个参数，结合饱和、噪声和延迟分析，不仅凭抖动外观判断。
4. 先争取短时抓住，再延长持续时间；记录角度峰值、RMS、释放角度、车体位移和输出饱和率。

验收顺序：可修正倾倒方向 → 松手保持 3–5s → 保持 10s。初期允许小车前后追杆，记录漂移但不急于用强位置环拉回。

### 阶段 D：减少漂移并完成稳定直立里程碑

1. 在阶段 C 稳定参数上，加入车速阻尼，再加入弱位置回中；参考位置在本次直立开始时建立。
2. 检查左右轮平均速度差，必要时添加有限的轮间补偿；IMU 不作为第一阶段必须新增的硬件。
3. 在同一配重下重复释放测试，再进行轻微前后扰动测试。

拟定验收：手扶释放后保持直立至少 20s，连续 5 次至少 4 次成功；角度大部分时间位于 ±5°，小车在起点前后约 ±0.3m 内活动且无持续单向加速。位置范围可按可用场地和实测能力调整，不能为了回中牺牲直立稳定性。

阶段 D 通过即完成用户当前第一目标。保留该版本、标定和参数作为可回退基线。

### 阶段 E：测量起摆所需参数

1. 称量转动总成，包括铝管、夹座、夹环、垫片和紧固件；测量重心位置与摆动阻尼，必要时用自由摆周期估计转动惯量。
2. 测量小车在地面上的驱动死区、正反向响应、可实现加速度、换向延迟和打滑情况；额定转速不能代替加速度能力。
3. 确认摆杆完整下垂/转动时实物无干涉，磁铁固定和 AS5600 全角度读取正常。

验收：有可复用的机械/驱动参数记录，明确可用行程和稳定捕捉范围。不会将 280mm 杆长直接填成单点摆等效长度。

### 阶段 F：自动起摆与捕捉

1. 使用基于能量误差的起摆策略，叠加较弱的小车回中约束；起摆命令需转换为实测执行器能实现的驱动力/加速度。
2. 以直立为 theta=0，物理摆能量可写为 E=0.5*J*omega^2 + m*g*lc*cos(theta)，直立目标 E*=m*g*lc。J 为整个摆动总成绕轴惯量，lc 为其重心距；最终控制符号须按本工程坐标推导。
3. 自然下垂且静止时，纯符号型能量控制可能没有启动方向，需设计一个可重复的小幅初始激励。
4. 接近直立时同时检查角度和角速度，并结合小车速度/位置是否适合捕捉，切入阶段 D 的直立控制器。
5. 切换采用滞回和输出衔接，避免反复切换；第一次先验证单次起摆，失败后的自动重试作为后续单独功能。

拟定验收：先完成 1 次自动起摆并保持 10s，再争取 10 次中至少 8 次成功且每次保持 20s。此时才讨论提高起摆速度和扩大捕捉范围。

能量起摆与局部直立控制分开设计的依据可参见 MIT Underactuated Robotics 的 Cart-Pole 与 Swing-Up Control 部分：https://underactuated.mit.edu/acrobot.html 。本文使用直立零角度，引用资料的角度零点不同，不直接照抄其符号。
