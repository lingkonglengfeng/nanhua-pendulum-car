# 长时间直立与差速转向

当前v37（0x103C8037）提供原地转向专用BALSPIN，保留平均里程位置保持而不只给平移零速；BALSPIN0停转后仍保持同一锚点。原BALTURN保留取消位置模式的语义，原地需求使用新模式。见[原地转向与零点整定](原地转向与零点整定.md)。以下为旧版说明。

当前v34（0x103C8034）增加[编码器平均里程位置保持](编码器平均里程位置保持.md)。BALPZERO可将当前地点记0并保持，BALPOS0回到同一编码器原点；非零转向取消保持，停转后需明确重选目标。转弯/打滑后的里程0不代表绝对地面同一点。原转向PI及阈值沿用v33，以下为旧版说明。

当前v33（0x103C8033）：转向PI默认0.008/0.010，新增BALTURNPI调参；直立输出80%、差动上限12%、退出顶端±30°。捕捉±1.4°/400ms和不限时保留，Y由8列追加为10列，详见[转向积分与30度退出](转向积分与30度退出.md)。下文v31/v32阈值和P控制说明为历史记录。

v32（0x103C8032）更新：转向P默认提高到0.008，差动限幅仍0.08；转向及速度控制改用低速周期/高速计数混合测速，新增H6日志，原计数测速用于超速检查。指令和运行时限含义不变，见[低速周期测速与转向增益](低速周期测速与转向增益.md)。下文v31增益0.003、测速路径和资源统计为历史值。

2026-10-18，固件 `0x103C8031`。默认取消原24秒ACTIVE试验时限，增加保持倒立时的差速转向；未自动烧录或驾驶实车。取消时限不等于已验证长期稳定：此前零速控制仍有慢漂、过冲，转向增益也需要实测。

## 开始与操作

烧录 `MDK-ARM/f103_bringup/f103_bringup.hex` 后，摆杆自然下垂、小车静止，逐行发送：

```text
STOP
BALSAFE 60 0
ZERO
```

`BALSAFE 60 0` 表示单轮60RPM连续50ms退出，运行时限关闭；源码默认也是60/0。非零时限仍接受500～60000ms，且这条配置命令会停止直立，需要重新ARM或ZERO。角度、传感器有效性、控制间隔等退出仍保留；并未改为无条件持续驱动。

标定成功后扶到最高点±1.4°连续400ms，进入ACTIVE。进入并松手后，一次只发一项测试指令，观察实际方向和Y/T/P日志：

| 指令 | 请求 |
| --- | --- |
| `BALTURN 5` | 右转，左右轮平均速度之差的目标为+10RPM |
| `BALTURN -5` | 左转，左右轮平均速度之差的目标为-10RPM |
| `BALTURN 0` | 差速目标归零，保持倒立，继续原来的平移目标 |
| `BALSPD 5` | 保持当前转向请求，平移目标正向5RPM，可形成弧线 |
| `BALSPD -5` | 平移目标反向5RPM，保留转向请求 |
| `BALSPD 0` 然后 `BALTURN 0` | 平移与差速目标均归零，保留直立 |
| `STOP` | 取消全部运动请求并撤驱动 |

`BALTURN` 参数范围±10，单位为 `(左侧平均RPM−右侧平均RPM)/2`，不是角度、角速度或PWM百分比。正值使左侧比右侧快，按本车前进方向定义右转。AS5600只测摆杆角，不测车体航向；轮胎打滑、地面摩擦会影响实际转角，不能发指令保证转90°。目标会保持到新命令或退出，不是定时点动。

BALTURN/BALSPD仅在ACTIVE且速度外环开启时接受，否则NOT_READY。两项目标绝对值之和不能超过超速阈值一半，且平移最大30RPM；非法命令整条拒绝。上电、STOP、ARM、ZERO、普通运动模式切换和任何保护退出都会清零转向请求，不能自动恢复旧转向。

## 控制与Watch

保留角度PID8.4/0/0.17、速度外环0.038/0.0009、±3°参考限幅、70%输出限幅、三点角度中值和10ms角速度低通。转向不启用四个独立车轮速度PI，仍由角度环负责共同前后输出。

物理电机通道0=右后、1=右前、2=左后、3=左前，原编码器映射和硬件极性不变。转向测速采用 `(fast2+fast3-fast0-fast1)/4`，50ms低通；差速目标变化率10RPM/s，P起点0.003归一化输出/RPM，无积分，最大差动输出±0.08。Watch可看/调整 `g_bal_turn_kp`，接受0～0.01，当前值仅是估算起点。

左右逻辑输出为 `左=直立输出+差动`、`右=直立输出−差动`。先保留共同直立输出，再按剩余输出余量压缩差动，确保两侧均不超过原70%限幅。直立饱和时差动降为0，因此不能把转向目标等同实际轮速差。两侧测速平均仍可能受轮滑或编码器噪声影响，Y行与T的四个fast速度需一起看。

Watch：`g_bal_turn_target_rpm`、`g_bal_turn_command_rpm`、`g_bal_turn_rpm`、`g_bal_turn_output`、`g_bal_turn_kp`。原 `g_bal_max_run_ms=0` 表示不启用到时退出；`g_bal_run_ms` 继续记录运行时间。零速目标不保证完全原地不漂，转向0也不保证保持绝对航向。

## 与直走返程的关系

`BALSPD` 与 `BALTURN` 独立：修改其中一个不会悄悄清除另一个。非零BALTURN会取消正在执行的BALSEQ并把平移目标设0，逐渐减速后转向；不能拐弯后继续声称原一维编码器原点仍是二维起点。BALTURN0不会取消序列。

启动BALSEQ要求转向请求与斜坡目标均为0；先BALTURN0并等斜坡回零再发送BALSEQ。BALSEQ自身仍为一维直走、停车、返程、原点保持，不增加航向闭环。不限时模式下，如果始终不能停稳/到位，序列会留在当前阶段，直到满足条件、用户取消或其它退出发生。

## 日志与验证

仅ACTIVE打印参数的策略保持。旧T16、B25、V16、E19、P9列不改，P附近每约100ms新增：

```text
Y,ms,target_rpm,command_rpm,diff_rpm,u,kp,limit
```

Y8列依次为请求、斜坡目标、低通后的半轮速差、已按平衡余量限幅的差动输出、P增益、差动最大限幅。Y/P来自日志任务临界区读取，和T控制快照时间相邻而非完全同步。全量协议CSV_V14；精简T格式仍TRACE_V2。退出后停止参数流，最终退出原因需看Watch的g_bal_reason，不能凭最后一条ACTIVE日志推定。

ARMCC5全量40源构建及控制/串口/日志/PWM回归通过。主机检查覆盖不限时跨tick回绕运行120秒、有限时限仍有效、左右转斜坡与测速、映射/平均输出保持、饱和优先平衡、流程冲突、STOP/故障复位、边界和NaN。测试是代码逻辑验证，不代表实车已连续平衡120秒。

Code42804、RO4516、RW776、ZI19600；RAM20376/20480（含预留堆栈），ROM47456字节。没有增加任务、动态分配或阻塞等待。精简首包1072/2048，最坏GET1376/2048，全量默认流估算8841B/s。实车后续仍需观察日志中的任务执行时间、漏周期和栈余量。v30备份在 `MDK-ARM/speed_pid_build/before_balance_turn_v31/`。
