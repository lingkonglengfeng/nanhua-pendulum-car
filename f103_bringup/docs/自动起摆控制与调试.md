## 首次操作

小车放在平整地面，摆杆自然下垂、全程可转且不碰车体，先发送：

```text
STOP
ZERO
```

ZERO回执只表示指令接受。保持静止至少约1秒，等待200点最低点标定完成，再单独发送：

```text
SWING
```

不要把SWING紧跟ZERO一次发完：标定尚未完成会返回NOT_READY。自动起摆时不需要把摆杆扶到顶端；手动扶起仍使用原ARM流程。SWING只在已经标定、传感器有效、距最低点约30°以内、角速度不超过0.5 rad/s且四轮基础测速绝对值不超过5 RPM时接受，否则拒绝，不排队等待启动。启动后四轮同向往复驱动，不执行转向或普通轮速PI。

`STOP` 随时撤驱动，零输出沿用原滑行方式。退出后不会自动再试；需自然下垂、静止后再次SWING。不要通过Watch直接改状态绕过启动条件。

## 当前参数

| 项目 | 默认值及串口设置 |
| --- | --- |
| 起摆最大输出、净里程边界、超时 | `SWINGCFG 35 2 10000`：35%、起点±2输出轴圈、10秒 |
| 能量增益、模型omega平方、接管角速度 | `SWINGENERGY 0.18 55 2`：0.18、55 s^-2、2 rad/s |
| 第一次启动激励方向 | `SWINGDIR 1`，可改-1，只影响最初150ms |
| 输出变化率 | 每秒3.0归一化占空比，5ms最多变化0.015 |
| 净里程回中/速度阻尼 | 0.08归一化输出/圈、0.002归一化输出/RPM |
| 直立控制 | 原PID8.4/0/0.17、共同限幅80%、位置P20/上限6 RPM、速度外环0.038/0.0009 |

SWINGCFG范围为10～60%、0.5～8圈、500～15000整数ms。SWINGENERGY范围为0.01～0.8、10～200、0.2～4 rad/s；SWINGDIR只接受±1。这些配置指令会停止当前模式，修改后再发SWING；修改仅保存在RAM，复位恢复源码默认。

用户允许按约2m活动区考虑，但轮胎实际直径未测。软件用四轮平均的编码器净圈数限制，既不是累计运动路程，也不能补偿打滑。若实际轮径恰好为旧CAD参考65mm，±2圈约为起点±0.408m；这只是换算示例，不是已实现准确的2m场地边界。

## 算法及接管

源码 `Core/Src/balance_swing.inc` 由原balance_control.c直接包含，不需要另加Keil编译条目。5ms控制周期、非阻塞状态机，无新任务或动态内存。

内部theta=0为最高点，±pi为最低点，归一化能量：

```text
E = 0.5 * rate^2 / omega2 + cos(theta)
E_target = 1.02
```

先给150ms有斜坡的启动激励，然后根据能量差、角速度和cos(theta)决定加能或减能，并叠加净里程回中与车速阻尼。输出始终限制在起摆限幅和直立共同限幅的较小者。omega2=55基于轴到尖端265mm、直径8mm、旧夹座近轴20mm的简化估计，连接件中空、实际插入深度/质量/惯量待测，不能认为是实测模型。电机PWM也不是已标定的车体加速度，因此不能直接套用理想能量控制的收敛证明。

自动接管需要同时满足：原始顶端角度在当前捕捉带内（默认±8°）；角速度≤2 rad/s；40ms线性预测角仍在捕捉带内；最近基础轮速峰值≤90 RPM且≤当前超速阈值。满足后立即进入ACTIVE，继承实际车速，重设进入位置为0并启用原位置保持。动态过顶不能等400ms，所以自动接管不等待该时长；手动ARM仍要求±8°连续400ms。

起摆状态 `g_bal_state=6`，与 `g_bal_seq_state=6` 的原地转向SPIN是不同变量。起摆时不使用直立±30°退出；接管后恢复该角度条件。起摆期间保留传感器/配置/模式冲突/控制间隔>15ms/任一轮>200RPM连续200ms退出，额外在净圈数达到边界或起摆超时时退出。退出均撤驱动并锁定，不自动重启。

## 日志判断

默认BALTRACE1：SWING期间40ms一次U，接管后恢复20ms一次原T，等待/关闭时仍静默；命令回执与一次X退出诊断保持。完整协议升为CSV_V21，旧日志列数保留。

```text
#F103_SWING_TRACE_V1,...,fw=0x103C8039
#U,ms,phase,bottom_deg,rate_rad_s,energy,target_energy,u,pos_rev,mean_rpm,limit,travel_rev,run_ms,max_run_ms,omega2,gain,capture_rate
```

U共17列，bottom_deg以最低点0°、最高点180°表示。phase1启动激励、2加减能、3已经接管、4中止。phase3会伴随第一次直立日志打印；后续看T.state=4及角度/速度/位置是否收敛，不能只凭接管认定已稳定20秒。完整GET在SWING时也包含U。

X.reason=10/TRAVEL表示净圈数边界，9/RUN_TIME表示本阶段超时，8/SPEED表示持续超速，3/SENSOR表示读角/测速异常，4/TIMING表示控制间隔异常。发回从SWING回执开始的完整U、接管后的T及最终X，便于区分没有加起摆幅、过顶太快、接管失败或行程限制。

## 与正弦起摆比较

正弦轨迹可设为 `x_ref=x0+A*sin(omega*t+phi)`，由车体位置/速度伺服去跟踪。幅度决定期望往复行程，频率影响加能时机；有摩擦、打滑、跟踪误差时，实际轨迹和相位会偏离，单纯把PWM写成sin并不能保证小车按正弦位移运动。两种方法最终都需要顶端接管。

[2010年UiTM论文的控制策略A节](https://ir.uitm.edu.my/id/eprint/61875/1/61875.pdf)给出水平小车正弦位置参考、PV闭环伺服和近顶端切换，属于可以参考的正弦轨迹方案。[MIT能量整形课程](https://underactuated.csail.mit.edu/acrobot.html)则给出能量误差反馈、车体回中项及精确最低点需要初始激励的原因。论文中的系统参数、伺服增益和接管阈值不能原样搬到本车。

两者也可以组合：[IFAC2002周期输入论文](https://www.sciencedirect.com/science/article/pii/S1474667015398591)通过状态/能量调节周期信号幅度，摘要验证为数值仿真。该文讨论的支点振动形式不可直接等同本车水平前后驱动；这里只用于说明周期输入与能量反馈可以结合，不作为本车已验证算法。

结合本车AS5600已可提供角度/角速度，而原零速/位置跟踪仍有波动，本轮先保留能量反馈作为实测基线，不同时加入另一套正弦控制。它减少了对固定往复频率的依赖，但仍依赖正确方向、角速度估计和足够的实际驱动力。后续若比较正弦，应先测小车伺服跟踪，再以同一输出/行程限制比较成功率、耗时、顶端角速度和接管后稳定性。
