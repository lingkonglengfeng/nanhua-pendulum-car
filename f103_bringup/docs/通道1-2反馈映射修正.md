# 通道 1、2 反馈映射修正（0x103C800E）

用户本轮日志从 0x103C800D 上电开始，只发送 SET 1 60、RUN 1，并确认实际两个轮子都动。

## 日志证据

1803～2403ms：电机1的输出从0.121增加到0.481，编码器1仍为0，电机2输出为0。2453ms时编码器2累计计数先变为-11，速度-28.85RPM；控制器把它误当作电机2的速度，尽管电机2目标为0，仍开始增加其输出。2903ms电机2输出0.538后，编码器1才出现计数。随后两个控制器互相使用另一个电机的反馈，形成联动和大幅波动。

这轮用于识别对应关系，不据此重新调Kp/Ki。先显式STOP清状态。

## 修正

本车F103默认电机到原始编码器映射从0/1/2/3改为0/2/1/3。正驱动电机1时编码器2初始为负，因此编码器2符号从-1改为+1。

| 电机通道 | PWM | 反馈原始编码器 | 编码器引脚 | 编码器符号 |
|---|---|---|---|---:|
| 0 | PA8 | 0 | PA0/PA1 | -1 |
| 1 | PA9 | 2 | PA6/PA7 | +1 |
| 2 | PA10 | 1 | PA4/PA5 | +1 |
| 3 | PA11 | 3 | PB12/PB13 | -1 |

电机符号保持-1/1/1/1，PID保持Kp=0.001562、Ki=0.01、Kd=0。原始g_enc_count/delta/speed索引没有重排；g_speed_current按新映射对应电机通道。F407分支保留原默认值。

这份日志能识别反馈串路；修正后仍需实车确认只驱动目标轮、正命令产生正反馈及物理前进方向，电机2和3也需分别验证。

## 不重刷时的串口操作

先发送STOP，等待轮子完全停止，再依次发送并等待OK回执：

```text
MAP 1 2
MAP 2 1
ENCSIGN 2 1
GET
```

随后架空单测：

```text
SET 1 60
RUN 1
```

先观察应只有目标轮转动，rpm1应向+60靠近，rpm2接近0；采约3～5秒，随后单独发送STOP。如仍有联动或反向，先STOP并保留新日志。

默认修正已写入源码，固件版本0x103C800E；串口修改是RAM参数，复位旧固件会丢失，下载新固件后默认即为新映射。未自动烧录。
