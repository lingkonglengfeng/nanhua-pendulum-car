## 默认行为

- 取四轮映射后的 `g_speed_fast[]`（已有20ms编码器低通，绕过前轮额外60ms滤波），计算绝对值最大值。
- 在ACTIVE期间，最大值连续50ms大于40RPM，触发reason=8。等于或低于阈值重置连续计时。NaN/无穷大测速触发传感器故障reason=3。
- 从进入ACTIVE起累计1500ms，触发reason=9。手扶400ms捕捉时间不计入运行时长。
- 在控制周期提交电机波形之前检查；触发后清使能、输出和积分，四轮请求归零，DMA生成00滑行。进入TRIPPED，不会因角度回到顶端而自行启动，需ARM。
- 既有角度、传感器、控制间隔、配置保护继续工作；轮位、方向、角度PID默认值及仅ACTIVE打印策略不变。B行25列及协议V7保持不变。

这些是软件撤驱动条件，不是硬件急停、主动刹车或硬速度上限。存在编码器滤波、50ms判定和执行延时，速度可能超过阈值；撤驱动后车仍会滑行，摆杆会失去主动稳定。电机电源断开后才能把它当作无驱动设备搬动。

## 串口与Watch

```text
BALSAFE 40 1500
```

RPM阈值范围10～280，可带小数；时间范围500～60000ms且必须为整数。两项保护始终启用，不接受0或NaN。命令只修改RAM并停止当前运行，需要ARM或ZERO才能重新捕捉。上电恢复40RPM、1500ms。

| Watch变量 | 含义 |
|---|---|
| g_bal_max_rpm | 单轮测速绝对值退出阈值，默认40 |
| g_bal_guard_rpm | 最近检查到的四轮最大绝对RPM |
| g_bal_max_run_ms | 本次ACTIVE最长运行时长，默认1500 |
| g_bal_run_ms | 最近运行累计时长，退出后保留 |
| g_bal_overspeed_ms | 连续超速时长，退出后保留 |
| g_bal_reason | 8超速退出、9到时退出；其它原因沿用旧值 |

仅ACTIVE打印参数的策略保持不变，退出后不额外发送参数，因此末条B可能仍为state=4。用Watch读退出原因；重新ARM/开始ZERO会清运行观察值。HELP会列出新命令。

## 下一次短试验

先烧录新版，摆杆在最低点静止，再逐行发送并等OK：

```text
STOP
BALPID 7 0 0.2
BALLIMIT 50
BALSAFE 40 1500
ZERO
```

ZERO采样约1秒后自动准备捕捉，无需在ZERO前再发ARM。仍须手扶顶端连续400ms才进入控制。这里将输出限幅降为50%；自动退出独立于BALLIMIT，设100%也不会关闭保护。7/0/0.2仍为候选参数，不代表已长期稳摆。先记录短时落地响应，后续根据平均轮速设计速度外环。
