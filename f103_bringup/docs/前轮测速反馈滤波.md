# 前轮测速反馈滤波试验（0x103C8012）

用户确认右前轮在OPEN 3 59时肉眼看起来平稳，而既有测速约33～93RPM波动。反馈量波动可能参与了闭环调制，先做有限滤波试验；肉眼平稳尚不能排除细微机械变化或编码器信号异常。本版不宣称根因已解决。

后续用户确认OPEN 0 10即可起转。代码及数据手册核对发现通道0正命令使用慢衰减，其它通道正命令使用快衰减。现在优先做同一轮正反向10%对照，见 [驱动正反向衰减模式差异](驱动正反向衰减模式差异.md)；不先把滤波试验当作驱动差异的修复，也不据此固化前轮PID。

后续日志 `logs/2026-10-18_025538/` 显示OPEN 3 40成功执行、CCR1440，约2秒累计仅增加1计数，基本停止；50%段也接近停止，60%段持续转动。40是固定输出百分比，不是40RPM。现阶段存在明显低输出死区迹象，准确的起转与维持阈值尚未测定，不增加最低PWM或启动强推补偿。

## 改动

原始累计计数、5ms增量和原20ms低通均保留。原测速映射到电机轮号后写入 `g_speed_fast[i]`，再按 `g_speed_filter_ms[i]` 做额外一阶低通，结果 `g_speed_current[i]` 才进入PID、误差和PC13判定。

F103默认额外低通tau为 `{0,60,0,60}` ms：只处理左前1、右前3；左后0、右后2为0，直接旁路，测速与增益保持此前行为。F407四轮默认旁路。这里60ms是低通时间常数，控制任务仍每5ms运行；额外滤波会引入响应延迟，尚需闭环日志和实物验证。

Watch可修改 `g_speed_filter_ms[i]`，0关闭额外低通，值大于200按200使用；有效值看只读 `g_speed_filter_used_ms[i]`。滤波在STOP/OPEN时也持续更新，PID RESET不清掉测速状态，避免启用闭环时人为重新从0估算已有运动。

PID基本参数与单轮覆盖规则没有变化；没有把前轮试验Ki写成默认值，没有自动启动车轮，没有添加电机故障停机路径。

## 下次先测试右前60RPM

STOP后下载0x103C8012，确认版本，逐行发送并等待OK：

```text
STOP
LOG 1
PIDW 3 0.0008 0.005 0
LED 3 5
SET 3 60
RUN 1
```

架空记录10～12秒后单独STOP。保存所有行，特别是F和D，同时反馈实际抖动是否减轻。灯更稳定可能仅由反馈滤波带来，不能单独用灯判定试验通过。要设置40RPM，应SET 3 40后RUN 1；OPEN 3 40只给固定40%输出，不会由积分自动克服死区。本轮先保持60RPM，以便与上一闭环试验比较。

## CSV_V4

D/C/S/W列数保持49/28/22/18。新增每次D后发送的10列F行：

`F,ms,tau_ms0,fast_rpm0,tau_ms1,fast_rpm1,tau_ms2,fast_rpm2,tau_ms3,fast_rpm3`

fast_rpm是原20ms测速，含原有低通，不是完全未处理的5ms原始测速；D.rpm是额外滤波后的闭环反馈。F的轮号采用电机编号；count/delta仍采用原始编码器编号，映射不变。GET也返回F行。比较时同时看F、D以及u/I/CCR，不能只看D曲线变平滑。

## 验证

生产滤波函数回归覆盖后轮旁路一致性、恒速与反转收敛、停止后衰减、抖动dt、tau上限、关闭滤波旁路、PID RESET保持测速连续。原有命令、单轮增益、DMA接收边界回归通过；格式回归确认F含有效tau和原测速，配置变化检测与全部列数正确。
