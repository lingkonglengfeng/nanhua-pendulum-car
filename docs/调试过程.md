# 调试过程整理

这份文档先按现有源码和记录梳理技术过程。文中的测量结果属于对应历史版本和实验条件；比赛现场经历与作者自己的感受，另见 [校赛复盘与个人经验](校赛复盘与个人经验.md)。

## 1. 先把通道、接线和方向对应清楚

四个电机能转以后，仍需要分别核对“命令控制哪个轮子”和“这个轮子的反馈来自哪个编码器”。本车后来的逐轮测试确认：电机 0 右后、1 右前、2 左后、3 左前，而反馈使用原始编码器的顺序是 `0/2/1/3`。

如果把这两套编号混用，可能出现控制一个轮子却使用另一个轮子的速度做闭环。改正反向时，也要分别看电机符号与原始编码器符号，不能按相同数组下标直接一起改。

参考：[反馈映射修正](../f103_bringup/docs/通道1-2反馈映射修正.md)、[最终确认的轮位表](../f103_bringup/docs/轮位与通道对应.md)、[四轮轮流测试](../f103_bringup/docs/四轮轮流测试说明.md)。早期记录的轮位名称可能已经失效，数据仍按当时的通道编号理解。

## 2. 用固定输出排查驱动，再调速度 PID

调试中曾出现正负方向在相同输出幅值下响应不同的问题。先使用 `OPEN` 固定输出，可以把驱动层的差异和速度 PID 的影响分开观察。

后续在保留原接线的前提下，用定时器触发 GPIO DMA，让两方向都采用慢衰减。对应 v13 的一轮记录中，正负 10% 固定输出跳过起转 1 秒后的累计计数平均速度分别约为 +25.25 和 -25.52 RPM，幅值差约 1.1%。这是当轮编码器响应的证据，不能代替引脚波形测量，也不能直接代表所有轮子的闭环效果。

参考：[固定输出对照](../f103_bringup/docs/右前轮固定输出对照.md)、[驱动正反向衰减差异](../f103_bringup/docs/驱动正反向衰减模式差异.md)、[双向慢衰减实现与实测](../f103_bringup/docs/不改线双向慢衰减PWM.md)、[单轮 PID 调试](../f103_bringup/docs/单轮PID调试.md)。

## 3. 分清真实轮速、测速波动与控制时序

速度曲线出现尖峰时，先看原始计数、边沿、采样周期和累计里程，再看滤波后的曲线。低速下每个采样周期的脉冲数较少，量化误差明显；外加低通能让曲线变平，但会引入延迟。重复中断、输入毛刺和真实加速需要不同的处理。

串口输出也会影响观察方式。工程后来使用独立日志任务及 DMA，并记录控制晚唤醒、漏周期与日志丢帧。日志丢帧、控制漏周期、编码器漏计是不同现象，应分别判断。

参考：[首轮日志分析](../f103_bringup/docs/首轮速度环日志分析.md)、[串口 DMA 日志](../f103_bringup/docs/串口DMA日志.md)、[编码器毛刺与重复中断](../f103_bringup/docs/编码器毛刺与重复中断检查.md)、[低速周期测速](../f103_bringup/docs/低速周期测速与转向增益.md)、[测速尖峰处理](../f103_bringup/docs/直立外环单轮测速尖峰处理.md)。

## 4. 摆角标定和极性要先于增益调整

当前流程在摆杆自然下垂时采集最低点，再推算相差半圈的顶端位置。软件机械角、最低点角和相对顶端偏角使用不同的零点，查看曲线前要先确认字段含义。

更换传感器或磁铁安装以后，需要重新核对物理最低点、最高点和角度方向。通信正常、磁场状态有效，并不能直接证明机械角度精度和安装对中正确。

直立控制还需要确认车辆输出方向与摆杆倾斜的关系。方向和零点没有确认前，单纯加大增益很难定位原因。

参考：[最低点标定与串口控制](../f103_bringup/docs/倒立摆串口控制与最低点标定.md)、[AS5600 排查](../f103_bringup/docs/AS5600排查说明.md)、[平衡点微调](../f103_bringup/docs/直立平衡点微调.md)、[实心铁棒参数记录](../f103_bringup/docs/实心铁棒默认参数.md)。

## 5. 直立、零速与位置保持分阶段处理

能保持摆杆直立，不等于小车会留在原地。工程逐步加入速度外环、平衡点偏置和编码器平均里程位置保持；不同环的输出和目标需要分别观察。

滤波、输出变化率和电机响应延迟也会影响外环。修改机械摆杆、重心或轮组后，旧参数适合作为对照记录，不能自动视为新结构的最终参数。

参考：[直立环记录](../f103_bringup/docs/直立环调参记录.md)、[零速外环与位置保持](../f103_bringup/docs/直立零速外环与位置保持整定.md)、[外环变化率与电机延迟](../f103_bringup/docs/外环变化率与电机延迟复核.md)、[编码器里程位置保持](../f103_bringup/docs/编码器平均里程位置保持.md)。

## 6. 自动起摆要看动态接管条件

自动起摆不能仅以“经过 180°”判断成功。当前逻辑同时检查角度窗口、角速度、预测角等条件，只有满足条件才切换到直立控制。

更换 AS5600 后的一轮 v42 日志中，摆杆多次经过顶端，但部分过顶角速度超过接管上限，另有样本的预测角超出窗口；最终记录为起摆超时。这个案例说明，应结合 U / B / T / X 状态行解释过程，不能只看角度曲线经过顶端就判断程序漏接管。

参考：[自动起摆实现](../f103_bringup/docs/自动起摆控制与调试.md)、[顶端接管修正](../f103_bringup/docs/自动起摆顶端接管修正.md)、[换传感器后未接管分析](../f103_bringup/docs/更换AS5600后起摆未接管分析.md)、[快速起摆试调](../f103_bringup/docs/新AS5600快速起摆试调.md)。

## 7. 运动流程也要检查状态推进条件

后来加入直立下的速度指令、差速转向和定距离流程。`BALSTEP` 的一轮调试暴露出：如果“保持 5 秒”要求位置与速度连续满足很小的窗口，平衡修正会不断重置计时，使流程长时间停留在等待阶段。

v47 把起点和终点的保持改成阶段经过 5 秒就推进，期间仍执行位置控制；到达距离目标后的停稳确认另行判断。固定经过时间与连续稳定时间是两个不同要求，需要从实际任务含义出发定义。

参考：[直立直走与返程](../f103_bringup/docs/直立直走停车返程测试.md)、[长时间直立与转向](../f103_bringup/docs/长时间直立与差速转向.md)、[保持 5 秒—直走 1 米—再保持 5 秒](../f103_bringup/docs/直立保持5秒直走1米再保持5秒.md)。
